# Attaching images and videos

**Attaching images and videos from the terminal (gh 2.100.0 or newer).** `gh pr create --attach` and `gh pr edit <N> --attach` upload the file and point the body at it. Reference the file in the body as `![alt](./shot.png)` and pass `--attach './shot.png#alt'`: the reference is rewritten to a `github.com/user-attachments` URL. An attached file the body doesn't reference is appended. Up to 50 files per command. Run it from the directory the relative paths resolve against. When that directory is outside a git repository (an evidence folder), export `GH_REPO` and `GH_HOST` first, or `gh` fails with *not a git repository*. Videos render as a player and take no alt text. If some uploads fail the PR is still created or updated and `gh` exits non-zero, so check the exit code. `gh pr edit --attach` without a body flag keeps the existing body and appends, but `--body-file` still replaces the whole body, so the warning above applies. After an upload the `./` references in the live body are `user-attachments` URLs, so the next edit starts from a fresh `gh pr view <N> --json body`. Fill a full SHA with `git rev-parse <short>`, not by hand. When `check-pr-body.mjs` warns that a recording predates the head, re-record, or add a line naming the later commits and why they can't change the take, checked with `git diff <recorded-sha> HEAD -- src`.

To replace a placeholder with a video in place: fetch the live body, put `![](./clip.webm)` where the video goes, then run `gh pr edit <N> --body-file body.md --attach ./clip.webm` from that file's directory so the relative path matches. `.webm` is accepted, and the reference becomes a bare `https://github.com/user-attachments/assets/<uuid>` line, which GitHub renders as a video player.

**A 404 on an opened image in a private repo is an expired link, not a failed upload.** The body keeps the `user-attachments` URL, but each page load serves the image through a `private-user-images.githubusercontent.com/...?jwt=` link signed for 5 minutes. Reload the PR and open it again. To check an upload, look for the `user-attachments` URL in `gh pr view <N> --json body`.
